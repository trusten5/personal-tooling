# personal-tooling

Tools I've built for myself. The common thread is that I ran into a problem, couldn't find something that solved it well, and built it instead.

I think building your own tools is an underrated skill — it forces you to think clearly about what you actually need, ships faster than most "real" projects, and leaves you with something you use every day. This repo is where that work lives.

Most of these are built with AI assistance. I use Claude to handle implementation while I drive the product decisions, architecture, and iteration. Getting good at that workflow — knowing what to ask for, when to push back, how to debug and extend AI-generated code — is increasingly valuable and I'm deliberately practicing it here.

---

## tools

### [fieldnotes](./fieldnotes/)
A personal CRM and career workspace for students and early-career engineers. Tracks networking contacts, job applications, company aspirations, and interactions. Includes a scratchpad with `@contact` and `#company` mentions that link back to your data.

Built because every CRM I tried was either built for sales teams or too generic to be useful for a student doing a serious job search.

---

## why this matters

The ability to identify a problem, spec a solution, and ship something working is the core loop of engineering. Doing it for yourself — with no deadline, no team, no requirements doc — is the purest version of that loop. You either build something useful or you don't.

These projects also gave me hands-on experience with product thinking, frontend architecture, data modeling, and AI-assisted development workflows. None of that came from a class.

---

## stack

Varies by project. Current tools use vanilla HTML/CSS/JS with localStorage for persistence — deliberately minimal, no setup required. Future projects will use whatever stack fits the problem.
